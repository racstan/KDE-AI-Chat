# Changelog

All notable changes to the **KDE AI Chat** project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed
- **Attached files are kept once as files, not inside the chat file.** Each attachment is stored in the chat's folder (`attachments/<chat>/<hash>.<ext>`, private, written once per file) and the chat file keeps only a short reference, so chats with pictures and documents stay small and save fast. Old chats are moved the next time they are saved, after the copy has been read back and checked. Incognito chats still write no files. Deleting a chat deletes its attachments.
- **Chats are read when you open them.** At start only the chat list is read; a chat's messages are read when you open it (search reads the rest the first time you search).

## [1.4.1] - 2026-10-29

Fixes from a review of the 1.4.0 release.

### Security
- **Replies can no longer make the widget load a web address by itself.** Some ways of writing a picture link in a reply (a title in single quotes or brackets, an address in angle brackets, reference-style links) slipped past the filter, and the chat loaded them as soon as the reply was shown. A prompt hidden in a web page or file could have used this to send parts of a chat to another server. Every picture in a reply now waits for a click.
- **Tool cards and model names are shown as plain text.** A name or detail from an OpenCode or Pi agent could also make the chat load a picture by itself.
- **Permission notifications only offer Allow when they show the whole command.** A long command was shortened in the notification, so Allow could approve more than you could see; such requests now open the chat instead.
- Notification text from replies is escaped, and "input needed" notifications of incognito chats no longer show the question or command.
- **A warning when a key would travel unencrypted.** The provider editor and Check setup say so when a provider with a key uses plain `http://` to another computer.
- Names and times checked by the helper (schedules, chats, files) no longer accept a trailing line break.

### Fixed
- **Edit, Retry or Regenerate while a message is queued runs one request.** The queued message used to start as well, and the request it replaced kept running unseen (using tokens; in OpenCode and Pi the agent kept working). Now the old request is stopped in every mode and the queued message goes after the new reply.
- Every visible text can be translated, with proper plural forms ("1 model", "2 models"), and sentences are no longer built from pieces that break other languages' word order.
- The widget's description in Add Widgets is up to date.

## [1.4.0] - 2026-10-29

### Added
- **Change model on model errors.** When a reply fails because of the model (it can't read images, or it isn't available on your account), the error card now has a **Change model** button instead of Open settings. With per-chat model settings on it opens the quick model picker for just this chat; otherwise it opens the widget's settings (Plasma can't open a settings page by name; Connection is the first page).
- **A notice when the mode changed in Settings.** If Settings now select another mode (Direct, OpenCode or Pi) for new chats than the open chat has, the chat says so: "This chat stays in Direct mode, because a chat can't change mode", with a **New chat** button and a dismiss button. The chat itself never changes mode.
- **More varied starting points in an empty chat.** The chips now show up to six: your prompt templates first (at most three, rotating when you have more), a **Continue: <chat>** chip that opens your most recent other chat, then built-in suggestions picked differently for each new chat. Direct chats get everyday tasks (write, summarise, translate, plan, recipes, ...), OpenCode and Pi chats get project tasks (explain this project, fix a bug, write tests, ...), and mornings and evenings add a "plan my day" or "reflect on today" suggestion. A chip only fills the message box; it never sends.
- **Animated and video avatars.** The AI's and your own avatar (Settings → Personality) can now also be an animated image (GIF, APNG, WebP) or a short video (MP4, WebM, MKV, MOV, M4V, OGV; offered only when Qt Multimedia is installed), like the panel icon. Videos are always silent and repeat; the file is checked the same way (refused over 20 MB, a warning over 5 MB). The settings keep the same `aiAvatar` and `userAvatar` values (a file path; the kind comes from the extension). Animations play only while shown, and a video that can't be played shows a plain icon.
- **Long and unfinished replies are kept.** A message over the 2,000,000-character display limit is no longer cut on disk: the whole text is stored and only the chat view shows it shortened. A reply that is still being written is saved every 20 seconds (in any mode); if the widget or plasmashell stops meanwhile, the chat opens with what had arrived, marked "(interrupted)" and never resumed.
- **A Support page and an avatar for you.** Settings has a new last page, **Support**, with the **Buy Me a Coffee** and **Read the terms** buttons (moved here from Appearance) and the Speech Note credit; the name, version, author and license are on the About page Plasma adds to every widget. In Settings → Personality you can now choose **your own avatar** (a theme icon, an image, an animated image or a short video, with the same checks as the AI's; new setting `userAvatar`, empty = none); it shows next to your messages in the chat.
- **Safer KRunner, Dolphin and ask requests.** A request left in the ask inbox never sends by itself when it has files: the files are attached, the question is put in the message box and you press Enter (a KRunner question without files still sends at once). Attached files must be real, readable files under your home folder (symlinks are resolved first); anything inside a hidden folder or a hidden file (`.ssh`, `.gnupg`, ...) is refused, and each refused file is named in the chat. Selecting more than 10 files in Dolphin now attaches the first 10 and shows a desktop notification ("Attached 10 of 25 files; the limit is 10"), and errors of `kdeaichat-ask` are shown as a notification when it runs without a terminal.
- **Private text stays off the command line.** Every helper command now sends its payload (memories, scheduled prompts, picture links, chat exports, everything) in a private 0600 file in `$XDG_RUNTIME_DIR` that the helper reads and deletes, as read-aloud text already did; only nine tiny commands with no private text (status checks, `prepare_chat_dir`, `get_pi_models`, the old key-file steps) still pass it as an argument. **Exporting a chat** uses the same route, so exports are no longer limited to about 90 KB (the new limit is 20 MB of text); a failed export now shows "Export failed: ..." in the chat, a too-large one says so, and the "exported" notification appears only after the file is really written (no `sh -c` any more).
- **Less left behind, less on the command line.** A finished scheduled run that the job itself announces (no widget running, or a failure) is now sent over D-Bus (`org.freedesktop.Notifications`), so the schedule name and the start of the reply no longer appear in a process list; the old `notify-send` is only a fallback and then shows just the schedule name and "A new reply is ready". The helper deletes private payload files older than an hour at each start (one the helper never got to read). Pictures pasted from the clipboard are now kept in `$XDG_RUNTIME_DIR` (not `/tmp`), and any left over for more than a day are removed.
- **First-run setup.** On a fresh install (no direct-mode provider with a model and, unless it is local, a key in KWallet) the empty chat shows a short setup card instead of the usual empty state, inside the popup: **Choose where your AI runs** lists the local servers found on this computer (Ollama, LM Studio, llama.cpp, vLLM, ...: one click sets one up, no key needed; a LiteLLM proxy that asks for a key goes to the key step) and the common online services (OpenAI, Anthropic, Google Gemini, OpenRouter, Groq, Mistral, NVIDIA NIM, DeepSeek, xAI). For an online service you paste the key (with a **Get a key** link to the provider's key page, for the well-known providers only: new `keyUrl` in the provider presets), **Check key** lists the models the provider offers (a wrong key says so and nothing is saved), you pick one, and **Save and continue** writes the key to KWallet only (never to the configuration) and the provider, without its key, to the provider list. A last screen offers **Send a test message** through the normal send path, or **Start chatting**. One line says that online services see your messages and local ones keep them on this computer, with a link to the terms. **Skip - I'll set it up in Settings** opens the Connection settings and keeps the card away (new setting `firstRunDismissed`); otherwise it is derived from the providers, so it disappears for good once one works. It never appears while OpenCode or Pi is the default mode or in an agent chat, and never changes a chat's mode.
- **Keyboard and screen reader pass.** Every control now has a name a screen reader (Orca) can say: icon-only buttons, the fields and drop-downs of all settings pages and the schedule editor, the chat's own settings, the rename boxes, the memory editor and the privacy badge. A message is read as "You said: …" or "<model> replied: …"; while a reply is being written only "<model> is writing a reply" is said, so the text isn't read again for every word. **Tab and Shift+Tab now leave every multi-line box** (the message box, the editors for a message, a memory, a project, a schedule, a chat's instructions and the Personality notes) instead of typing a tab, so the keyboard is never trapped in one. The privacy badge can be reached with Tab and shows its explanation on focus. Tests: `tests/test_accessible_names.py` (every control in the source has a name) and `tests/qml/tst_accessibility.qml` (the running chat and some settings pages, message names, Tab order and Esc). The small grey help text (times, model names, token counts, the memory list's empty line) is a little less dim (opacity 0.7) for readability in light and dark themes.
- **Where your messages go, in every chat.** The line above the message box now always ends with a small badge: "OpenRouter · online", "Ollama · this computer", "Ollama · your network" (a server on the local network) or "Pi agent" / "OpenCode agent", with the full sentence on hover and for screen readers. The empty chat says the same, and no longer claims an OpenCode or Pi chat stays on this computer: the agent runs here but sends your messages to the model it is set up with. An address that only looks local (such as `127.0.0.1.example.com`) counts as online.
- **Terms of use.** `TERMS.md` says in plain words how the widget may be used: no warranty, the widget collects nothing itself, your messages go only to the services you choose (under their terms), and you are responsible for your keys, the costs on your accounts (including scheduled prompts) and how you use the answers. Settings → Support has a **Read the terms** button with a short summary.
- **Settings → Storage: where the widget keeps its data and what uses the space.** A new page shows the data folder (`~/.local/share/kdeaichat`, or under `XDG_DATA_HOME`) with an **Open folder** button and the total used, then a line for each of chats, pictures, memories, schedules and their logs, backups, temporary files (spoken audio, recordings, logs) and the old voice engines (the programs and models earlier versions installed for read aloud and dictation, labelled "no longer used"; shown only while some are left), each with its size, **Open folder** and a plain explanation. **Remove…** is offered only for backups, temporary files and the old voice engines; it shows how much it frees and asks first, and the old voice engines' background services are stopped and removed with them. Chats, pictures and memories are never removed from here (they have their own controls), and the folder cannot be moved. Speech Note's models are only linked ("Speech models are kept by Speech Note", with Open folder when the folder exists): never counted, never removed, and neither are models of other apps (Handy, the HuggingFace cache). New helper commands `storage_usage` (disk use per item, symlinks never followed, time-capped) and `storage_remove` (fixed item names only: backups, caches, voice_old).
- **Find local servers (Settings → Connection).** A **Find local servers** button, and a quiet check each time the page opens in the direct mode, lists the AI programs answering on this computer: Ollama (11434), LM Studio (1234), llama.cpp server (8080), LiteLLM (4000), vLLM (8000) and other OpenAI-compatible servers (LocalAI, Jan on 1337), each with its address and how many models it has. **Use** adds it as a provider with its address and a model filled in (Ollama, LM Studio, llama.cpp and LiteLLM use their own presets, anything else "Other OpenAI-compatible") and opens the provider editor to pick another of the server's models. A server is named only when it identifies itself (Ollama's `/api/version`, LM Studio's `/api/v0/models`, llama.cpp's `/props`, LiteLLM's `/health/readiness`, vLLM's `owned_by`); otherwise it is "OpenAI-compatible server". The helper (`local_servers_scan`) only asks 127.0.0.1 on those six ports, with plain read-only requests of 0.7 s at most, in parallel; it sends no key or other secret, uses no proxy and follows no redirects. The quiet check shows nothing when nothing answers; the button says so.
- **Voice through Speech Note, the system voice or a speech server.** Dictation and read aloud now go through the separate app [Speech Note](https://github.com/mkiol/dsnote) (Flatpak [net.mkiol.SpeechNote](https://flathub.org/apps/net.mkiol.SpeechNote)) by Michał Kosciesza, MPL-2.0: speech, models and GPU support (NVIDIA, AMD, Vulkan) come from it, in any language you download a model for. The widget installs and runs no speech models itself. Both are off by default (`sttEnabled`, `voiceTtsEnabled`) and `sttEngine` and `voiceTtsEngine` default to `speechnote`. The widget starts Speech Note's background service when you dictate or read, and it stops by itself when idle. **Dictation:** the microphone button listens through Speech Note (a keepalive runs while listening), Stop writes the text into the message box (sent right away when "Send the transcript right away" is on), Esc drops it. **Read aloud:** the whole reply goes to Speech Note, which splits the sentences itself; Stop, Pause and Resume work, and reading ends when Speech Note is done; a speaker button under each reply and Ctrl+Shift+S (the selected text, else the picked message, else the last reply) start it, and the right-click menu of message text has Copy and Read aloud. **Other engines:** the **system voice** (Qt's text-to-speech with Speech Dispatcher, in the widget itself, nothing to install: used for read aloud until Speech Note is installed, without an error) and an **OpenAI-compatible speech server** for dictation (`/audio/transcriptions`) and read aloud (`/audio/speech`), with URL, model, voice and speed; its API keys are in KWallet (entries `stt-remote`, `tts-remote`), never in the settings or on a command line, and read-aloud text goes to the helper in a private file. The microphone for a speech server is recorded by `pw-record` (or `parecord`/`arecord`) at 16 kHz into a private folder under `$XDG_RUNTIME_DIR` and deleted right after. **Settings → Voice:** two switches; a Speech Note status (installed as Flatpak or natively, or not installed, with links to Flathub and GitHub and a one-line setup), a model picker for each (`sttSpeechNoteModel`, `voiceTtsSpeechNoteModel`; empty = Speech Note's own default), "Say Hello", a Test button for the speech server (it sends a bundled recording; no microphone) and a credit line. **No lost words, no cold waits:** Speech Note's service exits after about a minute idle and a cold start takes several seconds, so the chat says "Starting Speech Note… please wait" and switches to "Listening — speak now" only when it is really listening; opening the popup starts the service in the background, and it is kept ready while the popup is open and for `speechNoteKeepReadyMinutes` (default 5, 0 = only when used) after it closes. Check setup looks at the recorder and address of a speech server, Speech Dispatcher, and whether Speech Note is installed and has a model. **The widget's own speech engines are gone** (they were only ever in unreleased builds or are replaced): faster-whisper, whisper.cpp, Parakeet, Kokoro (neural and as a Qt plugin), Flite, Piper and the custom commands for both, with their install, model download and Remove buttons, their on-demand `kde-ai-stt.socket` service and Python environments. **Upgrade:** a saved engine of those becomes Speech Note (read aloud uses the system voice until Speech Note is installed); their settings are removed from Plasma's config; at the first start the old systemd user units (`kde-ai-tts.service`, `kde-ai-stt.service`, `kde-ai-stt.socket`) are stopped, disabled and deleted. The old Python environments and models stay on disk until you delete them in Settings → Storage ("Old voice engines", with confirmation). New helper commands `speechnote_*`; `voice_startup` now removes all the old units; the `stt_*` commands remain only for the speech server (`stt_transcribe`, `stt_test`, `stt_dictate`, `stt_stop`) and `tts_synthesize`/`tts_cleanup` for its read aloud.
- **Look, layout and behaviour options, all opt-in.** With the defaults the widget looks and behaves exactly as before and follows the Plasma theme. Settings → Appearance → **Chat look**: text size of the messages and the message box (`chatFontScale`, 100 %), spacing compact / normal / roomy (`chatDensity`), plain messages or bubbles (`chatStyle`), code colours (`codeTheme`: Plasma colours, light, dark, Solarized light/dark, high contrast) and an accent colour for the chat's own highlights (`accentColor`, empty = the Plasma accent). **Layout**: the size the chat opens at (the existing `customPopupWidth`/`customPopupHeight`, also set by the resize grip), the history on the left or right (`historySide`), the folder and project bar shown or hidden (`showWorkspaceBar`; OpenCode chats keep it for the agent choice) and which buttons the top of the chat shows (`headerShowHistory`, `headerShowPin`, `headerShowSettings`, `headerShowNewChat`, `headerShowInfo`; More always stays). Settings → Chat → **Behaviour**: Enter or Ctrl+Enter sends (`sendKey`; the other one adds a line), follow the answer while it is written (`autoScroll`; off: a "New messages" button instead), times 24-hour, 12-hour or the region's format (`timeFormat`), ask before deleting a chat (`confirmDeleteChat`) and start a new chat each time the widget opens (`newChatOnOpen`; an empty chat is reused). Each option has a small reset button, enabled when it differs from its default, and both pages have **Reset this page** (the prompt templates are kept). The defaults live in `chat/Prefs.js` and match `main.xml` (tested).
- **Search across all chats.** A search field at the top of the history (**Ctrl+Shift+F** opens the history with it focused) finds text in chat names and messages in every chat of this widget, archived chats and chats in projects included (each result says "Archived" or the project's name). A result shows the chat, the date and the text around the match with the match marked; clicking it (or Enter) opens that chat at the message. Down/Up move through the results, Esc clears the field. The search runs over the chats the widget already has in memory once typing pauses (no helper process, no files read again); at most 5 matches per chat and 100 in all are listed, newest first. An incognito chat is never in the results.
- **Incognito chat: a chat that is never written to disk.** Start one with the button next to New chat or **Ctrl+Shift+N**. It works in the main mode, and the header marks it with an icon and "Incognito — not saved" and a button to close it. No chat file or index entry is written for it, it is never remembered as the last chat, it is not in the history or in search, no schedule can target it, the model is not asked to name it, and notifications don't show its name or text. Memories are neither used in it nor saved from it (Remember and `/remember` say so), so nothing personal goes in or out. It is gone when you leave it (another chat, New chat, its close button) or when the widget restarts; leaving one that has messages asks first, with "Don't ask again" (new setting on Settings → Chat, `incognitoAskBeforeLeaving`, on by default). Pictures in it are kept as files only while it is open (the widget shows images from files) and deleted when it closes, or at the next start if the widget ended with it open (new helper command `incognito_cleanup`, which also removes Pi's instructions file and empty working folder for it). In Pi mode it runs with `--no-session`, so Pi keeps no session file; in OpenCode mode OpenCode stores the session itself while the chat is open and it is deleted from OpenCode when the chat closes.
- **Every setting is explained in plain words.** Each setting on every settings page (Connection with its provider, OpenCode, Pi and picture-service forms, Chat, Personality, Memory, the schedule editor, Voice with every engine option, Appearance) and in a chat's own settings in the Chat info panel has a short line under it saying what it does and when to change it, written for someone with no technical background ("API key: the password-like code your AI provider gives you…"), with a longer hover text where useful. A test reads the settings forms and fails when a new setting comes without its explanation.
- **Animated panel icon.** Settings → Appearance → Panel icon: the normal icon, an animated image (GIF, APNG, WebP) or a short muted looping video (only offered when Qt Multimedia is installed). A file over 20 MB is refused and one over 5 MB gets a warning. The animation pauses while the panel is hidden or the screen is locked, can be set to play only while the pointer is on it, and a missing or unplayable file falls back to the normal icon.
- **Check setup (Settings → Connection).** One button checks what the current settings need on this computer and lists each thing with ✓, ⚠ or ✗ and a one-line fix: KWallet locked or off, a provider without a key, a malformed address or no model; Ollama, LM Studio or another local server not running (connection refused), too slow (timeout) or at the wrong path (404 on /models); OpenCode not installed, not answering or something else on its port (with its version); Pi not installed, its bridge; pdftotext and pandoc for attachments; dictation (Speech Note, or a speech server and the recorder) and read aloud (Speech Note, Speech Dispatcher, a speech server) only when they're on; and schedules whose systemd timer is missing, with **Recreate timers** (the existing timer sync). It only looks: nothing is installed, started or downloaded, and no key is read for it (helper command `setup_check`).
- **Errors in the chat offer Check setup.** A missing key, an unset chat, an unreachable provider or server, a timeout, or an agent that isn't installed or running now shows a **Check setup** button on the error card; it lists the problems found right under the error.
- **Old settings are removed from Plasma's config.** A while after start, once the 1.4.0 moves are done, the settings older versions left in this widget's group of `plasma-org.kde.plasma.desktop-appletsrc` are deleted: the 85 that 1.4.0 no longer has (plasmashell auto-restart, MCP, system info, shortcuts, old image and provider fields, …), the old plaintext key settings once they are empty (moved to KWallet), the old memory settings once the memory moved, the old dictation settings once they were copied, and the emptied chat history. Only this widget's own group is touched, under KConfig's lock, after a backup to `~/.local/share/kdeaichat/backups/appletsrc-<date>` (the last five are kept); nothing is written when there is nothing to remove.
- **Drag a chat onto a project**: in the history, drag a chat row with the mouse or touchpad and drop it on a project to move it there (the same move as Move to project; the chat keeps its mode). Touch still scrolls the list.
- **Schedules, new back end.** A schedule now has a list of timing rules and fires at their union: once, daily (every N days), weekly (weekday chips, every N weeks), monthly (a day 1–31 or the last day, every N months), hourly (every 1/2/3/4/6/8/12 hours at a minute, optionally between two hours), every N minutes (15 minimum) and cron (advanced/imported), each with several times. "Mondays at 16:00 and the other days at 15:00" is two weekly rules. Plus start/end dates, a run limit and a catch-up option (off by default; on: one run for times missed within 12 h). Definitions live in `~/.local/share/kdeaichat/schedules.v2.json` (written only by the widget); run state (last run, count, missed/skipped history trimmed to `historyLimit`) in `schedule-runs/<id>.json` (written only by the job), both atomic and private. One stdlib engine gives the plain-language summary ("Tue–Sun 15:00", "Every 2 days at 09:00"), the next runs, warnings (02:00–03:00 daylight-saving times, months without day 31, "never runs") and the run/skip decision. Each enabled schedule gets a systemd user timer `kdeaichat-sched-<id>.timer` (one `OnCalendar=` line per rule time, cron's day-of-month OR weekday as two lines, last day as `*-*~01`; checked with `systemd-analyze` before saving) that starts the shared `kdeaichat-run@.service`; systemd only wakes the job and Python decides (every-N days/weeks/months, start/end dates, already ran, edited since, catch-up window). New helper commands `schedules_list`, `schedule_preview`, `schedule_save`, `schedule_delete`, `schedule_history`, `schedules_sync` and `run_schedule <id>`. **Migration:** the old `schedules.json` is converted once into `schedules.v2.json` from the fields you picked (fixing the old cron bugs: "every N weeks" is kept, hourly keeps its minute), with a backup `schedules.v1.json`; the old file is left as it was. Incomplete old entries come over switched off and marked for review.
- **Scheduled prompts run by themselves, in the chat's own mode.** When a schedule is due, its systemd timer runs the prompt without the widget: a direct chat calls its provider (non-streaming; the key is read from KWallet over D-Bus, and if KWallet is locked the run is skipped, recorded as "skipped: wallet locked" and a notification says so), an OpenCode chat uses its own OpenCode session and folder (a temporary local `opencode serve` is started for the run when none answers, and stopped afterwards), a Pi chat goes through the Pi bridge in the chat's folder. The chat's provider, model, system prompt (Personality, extra instructions, project and chat instructions, response length) and its recent messages (same "earlier messages" limit) are used as in the widget; memories, tools and attachments are not. The prompt may use `{{date}}`, `{{time}}`, `{{weekday}}` and `{{last_run}}` (the last successful run). Nobody can answer an agent's permission request or question during a scheduled run, so they are declined and the reply says so. The prompt and the reply are added to the chat (marked as scheduled) and the run's result (ok / error / skipped, with the reason) goes into the schedule's history; runs that failed or were skipped don't count toward a run limit. The open widget picks the reply up at once without polling (it watches the chat folder) and never switches the chat you are in; "<schedule> is ready" opens that chat when clicked. With Plasma not running, or when a run fails, the notification comes from the job itself (no click action).
- **Schedules, new editor.** Settings → Schedules is now **New schedule…** and the list (no global switch and no daemon buttons: each schedule has its own on/off switch): each schedule shows its name, chat, a plain summary ("Mon 16:00; Tue–Sun 15:00"), the next run, the last result (sent, failed with the reason, missed, …), an on/off switch, Edit, History (when each run happened and what came of it) and Delete (asks first). Schedules brought over from the old scheduler that lack a chat or a time say so ("Needs a chat and a time") and open ready to finish. The editor has a name, the chat (this widget's chats), the message and the timing rules: add and remove rules, each one weekly (weekday chips, every N weeks), every day / every N days, monthly (a day or "Last day of the month"), once, every N hours (1/2/3/4/6/8/12, at a minute, between two hours), every N minutes (15 minimum) or a custom cron line, each with several times; a new weekly rule ticks the days the other rules leave free, so "Mondays at 16:00, the other days at 15:00" takes two clicks. A live preview (from the helper, 300 ms after each change) shows each rule's summary, the whole schedule, the next three runs and warnings (daylight-saving times, months without day 31, never runs). **More options**: start and end date, stop after N runs, run once when back if missed (off by default; within 12 h unless changed) and the notification. The helper's validation error is shown in the editor and nothing closes until the save worked. **Describe when**: type "weekdays at 9 and Sunday at noon" and **Fill in** asks the main settings' provider and model (Settings → Connection; not OpenCode or Pi) once for the rules as JSON; when the sentence can be read two ways ("every other day": the remaining weekdays or alternate days?) the model asks, with an answer button per reading and a free answer, until it can give rules. The rules are checked by the helper and put in the editor for you to review; nothing is saved by it. **Schedule a message…** in the chat's ⋮ menu opens the same editor over the chat with that chat chosen. A message a schedule sent shows "Scheduled: <name>" next to your name. The 1,391-line `ScheduleDialog.qml` and `config/SchedulerService.qml` (daemon start/stop/auto-start buttons) are replaced by small components in `config/` (`ScheduleDraft.js` and `ScheduleDescribe.js` are plain JS, tested with node). The settings `schedulerEnabled` and `executeMissedSchedules` are removed (the old "send missed messages" choice became each migrated schedule's catch-up option). `scripts/dev-run.sh` sets `KDEAICHAT_UNIT_DIR`/`KDEAICHAT_SYSTEMCTL` so a dev run never creates a real timer.
- **Projects**: group chats into projects. The history starts with **All chats**, each project (with its colour and how many chats it has) and **Archived**; choosing one filters the list. Create a project with the folder button, edit it with the pencil (name, colour, instructions, working folder, and optionally a model for direct chats), delete it from its menu, either keeping its chats (they move to no project) or, after a confirmation that says how many, **with its chats** (each deleted as a single chat is, with its memories, pictures and scheduled messages); **Undo** brings it all back (not the scheduled messages). Move a chat into a project from its menu (the header's More menu, or right-click / the Menu key on a history row, which also offers "New project…"); start a chat in a project with the **+** next to its name. A project's instructions go to every chat in it (after the main instructions, before the chat's own) in direct, OpenCode and Pi mode (Pi gets them through a private file, never on a command line); its folder is where OpenCode and Pi work unless the chat has its own; its model applies to direct chats (the chat's own settings first, then the project, then the main settings). Chat info and the folder row say what comes from the project. A project never changes a chat's mode. Projects are stored in `projects.ini` next to the chats; chats from before have no project and load unchanged. `DEV_PROJECT="…" scripts/dev-send.sh …` sends in a chat inside a project.
- **Memory, redesigned**: memories are separate short notes, each for every chat, for one project's chats or for one chat, and each can be pinned or turned off. They are kept in a private `~/.local/share/kdeaichat/memory.json` (0600 in a 0700 folder, written atomically by the helper; never in the widget's config), shared by all your KDE AI Chat widgets, with up to 1000 notes of up to 4000 characters. Each request takes the pinned notes and the ones that best match the message being answered and the two before it (keyword ranking), within a size you choose (new setting `memoryBudget` on Settings → Memory: 2000 characters by default, any amount, or no limit), and sends them as a short "Things the user asked you to remember" list: in the system prompt for direct and OpenCode chats, in Pi's instructions for Pi chats (a different choice starts Pi again on the same session). The notes sent are recorded on the chat (`memoryUsedIds`) for Chat info. Memory can be turned off everywhere (new setting `memoryEnabled`, on by default) or for one chat (`memoryOff`). Deleting a chat or project deletes its notes; Undo brings them back. **Migration:** the old memory text from the settings and each chat's old chat memory become notes (one per line, bullets removed; ones that were off come in turned off), and the old copies are cleared only after the new list was read back with all of them; running it again adds nothing twice.
- **Save and manage memories** (only you save them; nothing is suggested by the AI). **Remember** under a message (bookmark button) opens a small editor with the message, or the text you selected, cut to 4000 characters, and asks where it applies: all chats (the default), the chat's project (when it is in one) or this chat only. **`/remember <text>`** saves a note for all chats without sending anything (`/remember chat: …` or `/remember project: …` narrows it; `/remember` alone shows how). Both confirm with "Saved to memory" and **Undo**; saving a note you already have says "Already in memory" and turns it on if it was off. New page **Settings → Memory**: memory on or off for every chat, a one-line note on what is sent, and the list of notes with search, a filter (all chats / a project / one chat / turned off), Add, and per note on/off, pin, edit in place and delete (with Undo); scopes show the chat or project name. Notes brought over from the old memory start off, so the page offers **Turn on all**. **Chat info** has a Memory section: "Use memories in this chat" (applies at once) and the notes the latest message was sent with.
- **Pictures in replies** (direct mode): images a model sends back (OpenRouter `message.images` / `delta.images`, OpenAI-style image parts and base64 results, Markdown `data:` images) are saved as files in the chat's folder (`~/.local/share/kdeaichat/chats/applet-<id>/images/<chat>/<message>-<n>.<png|jpg|webp|gif>`, private, written by the helper) and shown in the message. The helper accepts only PNG, JPEG, WebP and GIF, judged by the file's first bytes (not its name or the server's content type), with a 12 MB cap per image. A message keeps only relative paths and notes (prompt, service, model, size, seed), never picture data or a signed link. Click a picture to enlarge it; each has **Copy image** (the helper puts it on the clipboard with `wl-copy` on Wayland or `xclip` on X11, since Plasma's QML cannot copy images; if neither is installed it says so), **Download** (a Save dialog) and, for pictures the widget generated, **Regenerate** (same prompt, a new image). Markdown image links in a reply (`![alt](https://...)`) are never loaded by themselves (Qt would fetch them): the text shows `[image: alt]` and a button "Show image from <site>" loads the picture only when you click, through the helper, https only, public hosts only (checked by `Security.js` and again when connecting), size-capped. Deleting a message or chat deletes its picture files shortly after, so Undo still works. Exports list the pictures: Markdown uses `![prompt](images/<chat>/<file>)` links, relative to the chat's folder, and JSON has an `images` list with the notes (the pictures themselves are not inside the export).
- **Image services** (direct mode, Settings → Connection → Add provider): **AI Horde** (community-run, works without an account through its documented anonymous key; your own key is optional and kept in KWallet) and **Pollinations.ai**, either with your own key (the documented `gen.pollinations.ai` API) or without one through the older free service (labelled as such: it may stop working, makes one picture every 45 seconds and adds a Pollinations logo; the widget keeps the 45 s gap with a countdown and honours 402/429 and `Retry-After`, never retrying by itself). Each service starts switched off: its form says in plain words that the prompt goes to the service (for AI Horde, to a volunteer's computer, and anonymous pictures are shared with LAION), links its terms, and you switch it on yourself. Live model lists (AI Horde: models with workers, adult-content models left out by the list's flags and a name blocklist, `nsfw: false` on every request), picture size, steps, count and seed within each service's limits (AI Horde without an account: up to 576 px, 30 steps, one picture at a time; 512×512 and 22 steps by default). AI Horde requests name the app honestly (`Client-Agent: KDE-AI-Chat:<version>:<website>`). A chat that uses an image service turns each message into pictures and stays a direct chat. Only the prompt is sent, never the chat.
- **`/image <prompt>`** in any direct chat makes a picture with the default image service ("Use for /image" in the provider list; the first one otherwise). While it works the reply shows AI Horde's queue place and wait time (checked every 4 s, every 10 s after a minute) or the free Pollinations countdown, with **Stop**, which cancels the AI Horde job (`DELETE`). Failures (kudos needed, no worker for the model, safety filter, limits, offline) appear as plain-words error cards.
- **"Input needed" notifications** (Settings → Appearance → Notifications, on by default): when the AI asks a question (direct `ask_user`, OpenCode or Pi) or an agent asks for permission while the popup is closed, or the open chat is another one, Plasma shows a notification with the question. Up to three answers are buttons on it, a typed answer goes in Plasma's inline reply box, and a permission is Allow / Deny. Answering there answers the card exactly as the card would; clicking the notification opens the widget (on a server without inline replies the Reply button opens the chat). It closes by itself when you answer the card in the widget.
- **One name per run of messages**: the sender's name and time show only on the first message of a run from the same sender (you, or the AI with the same model), like a group chat. The AI's tool steps, its questions and permission requests and its answer are one run, in every mode, until you write something or an error comes in. Question and permission cards have a plain heading ("Question", "Permission request") instead of repeating the model name.
- **The AI can ask you a question in direct chats** (new setting Settings → Chat → "Let the AI ask me questions", on by default). Direct requests now carry tools, handled for OpenAI-compatible APIs (streamed `tool_calls`), Anthropic (`tool_use`) and Gemini through its OpenAI-style endpoint. The first tool is `ask_user` (question, optional answer buttons, typed answer allowed unless the model says otherwise): the same question card the OpenCode and Pi agents use appears in the chat, you tap an option or type an answer, and the model carries on with it. Tool calls show as tool cards on the reply, are saved with the chat (so resending, regenerating and Export chat keep working) and go back to the provider as proper tool messages, or as plain text for a model without tools. If a model's server refuses tools (HTTP 400 naming them) the request is sent again without them and that model is remembered as having none until the widget restarts. Stop, or writing a message instead of answering, closes the question ("The user did not answer") and ends the request cleanly. At most 8 tool rounds per reply. `DEV_AUTO_ANSWER="text" scripts/dev-send.sh …` answers questions in the dev sandbox for end-to-end runs.
- **Slash commands in the message box**: typing "/" lists built-in commands first, then your prompt templates (Up/Down move in the list, Tab completes, Enter runs a command). `/model [name]` changes this chat's model (no name opens the model picker; it follows the same per-chat settings switch as the picker), `/variant [name]` changes its variant or thinking level (only listed when the model has variants), `/new` starts a new chat, and `/mode <direct|opencode|pi>` sets the mode of **new** chats only (the open chat keeps its mode). A command is never sent to the model and shows a short result under the box. Text starting with "/" that is no command or template (like "/etc/hosts?") is sent as a normal message. The empty-chat hint now reads "/ for commands and templates".
- **Browse messages with the keyboard**: with the message box empty (or not focused), Up/Down pick the previous/next message (highlighted, scrolled into view, with its action buttons shown); Down past the latest returns to the box, Esc clears the pick, and typing a character goes back to the box. PageUp/PageDown jump to the first/latest message (in a box with text only when the text does not itself scroll). **Changed:** editing your last message moved from Up to **Ctrl+E**. All listed in Settings → Appearance.
- **Copy an error**: error cards have a Copy button (tooltip "Copy error") that copies the full message with its HTTP status, URL and the provider's detail.
- **A wrong API key is caught when you save it** (Settings → Providers): a new or changed key is checked with the provider first. A rejected key (401/403) is not saved and the editor says so ("NVIDIA NIM rejected this key (403). Check you copied the whole key."). Providers that list their models for any key, like NVIDIA NIM, are checked with a one-token request to the chosen model. If the provider cannot be reached you can choose "Save anyway". Local servers without a key are not checked.
- **Live, usable model lists**: opening a provider in Settings → Providers lists its models without pressing a button (Refresh updates the list; it is kept for the settings session). Embedding, reranking, safety/guard, reward, speech and image models are hidden, with a "Show all models" switch. The chosen model is tried on save: a model the provider has retired or does not give your account (HTTP 404/410, "end of life") is flagged with the provider's reason, marked "(unavailable)" in the list, shown next to the provider and in the per-chat model settings, and needs "Use this model anyway" to save. The per-chat model picker uses the same live chat-model list.
- **The chat's mode, provider, model and variant are in Chat info** ("Direct · NVIDIA NIM · nemotron-3.5-bolt-e4b", "OpenCode · … · agent build", "Pi · … · thinking high"), on one line under "This chat" with a **Change…** button that opens the quick picker there (model, Pi's thinking level or OpenCode's variant and agent; no need to scroll to the settings below). The mode is shown but never changeable. With "Let chats have their own model settings" off, the picker says so and offers the settings. `/model` and `/variant` without a name open the same picker above the message box. The key hint ("Enter sends · …") only shows in a new empty chat.
- **Quote a message** (Discord-style): every user and assistant message has a **Quote** button (and **Ctrl+Q** quotes the message picked with Up/Down; listed in Settings → Appearance). The quote shows as a removable chip above the message box (speaker and first line; several quotes are kept in order, the same message is added once, and focus goes to the box). Chips are dropped when you switch chats. When you send, the quoted text goes to the AI together with your message in every mode (direct, OpenCode and Pi), as a block quote with a short speaker label in front of your text: `> Quoted (assistant):` followed by the quoted lines each starting with `> `, a blank line, then the message. A quote is cut at 4000 characters (with "…") and a message takes at most 10 quotes. The sent message shows the quotes in small blocks above its text; clicking one jumps to the original message and picks it if it is still in the chat. Quotes are kept with the message (saved chats, edit and resend keep them), and exports show them as Markdown block quotes (plain text: `> You: …`; JSON: a `quotes` list).
- **Model variants (reasoning levels) in every mode, only where the source reports them.** A variant picker appears next to the model only when the selected model has variants, and nothing is shown or sent otherwise. Direct: OpenRouter's `reasoning.supported_efforts` (sent as `reasoning: {effort}`) and Anthropic's `capabilities.effort` / `capabilities.thinking` (adaptive thinking plus `output_config.effort`; older Claude models get thinking on/off with one 8000-token budget) are read from the model list that is fetched anyway and cached with it per provider; a local Ollama says which models think through `/api/show` (variant "Thinking off"). Providers that report nothing (OpenAI, NVIDIA NIM, Groq, Mistral, Gemini's OpenAI-style list, ...) get no picker. OpenCode: the variant names per model come from the server's `/config/providers` (only the names are kept; the response also holds your API keys and is never stored or logged) and are sent as `variant` with the prompt. Pi: Pi's own thinking levels, only for models `pi --list-models` marks as thinking. The variant is chosen in Settings → Connection (direct: in the provider editor, per provider; OpenCode and Pi: next to the model), the Chat info panel and the quick picker (Chat info → Change…, or `/variant`; chips, with the variant shown on the Chat info line), and follows the same "this chat's settings win / main settings win" rule as the model. Only the variant's id is stored; an id the model no longer offers sends nothing.
- **Personality: you and the AI** (new Settings page **Personality**): tell the AI about you (your name, a few lines about you, the tone you like: Friendly, Professional, Concise or Playful, the language replies should be in, and "always / never" notes) and give the AI a name, a personality (None, Friendly, Professional, Witty, Mentor, Concise or your own words) and an avatar (a theme icon from KDE's icon chooser, or a PNG/JPEG/WebP/GIF/SVG/BMP picture). In the chat your messages show your name instead of "You" and replies show the AI's name and avatar with the model in small type beside it; exports use the same names (JSON lists them as `userName` / `aiName`). Direct chats get a short block made only from what you filled in ("## About the user" … "## Your persona" …, each field cut to a few hundred characters) at the very start of the system prompt; OpenCode and Pi chats keep their own instructions and don't get it. A chat can turn it off in its own settings ("Use my Personality settings", saved as `personalityOff`), independently of its own instructions. With nothing filled in nothing is sent and the chat looks as before. New settings `userName`, `userAbout`, `userTone`, `userLanguage`, `userNotes`, `aiName`, `aiPersonality`, `aiPersonalityCustom`, `aiAvatar` (plain text, never secrets).
- **Ask about the selected text, from any app (Settings → Desktop integration, off by default).** Select text anywhere and press **Meta+Alt+A** (not used by Plasma's defaults): the widget opens with the selection quoted as a "> ..." block in the message box and the cursor below it; nothing is sent until you type your question and send. The text is the primary selection (`wl-paste --primary` on Wayland, `xclip`/`xsel` on X11, no Ctrl+C needed); when nothing is selected the clipboard is quoted instead and a notice (never containing the text) says so. The shortcut is an ordinary application entry, `~/.local/share/applications/kdeaichat-ask-selection.desktop`, running `kdeaichat-ask --selection` with `X-KDE-Shortcuts=Meta+Alt+A`: Plasma lists it in System Settings → Keyboard → Shortcuts, where you can change or remove the key. It is installed and removed by `desktop_sync` (marker file only, atomic, a file that is not ours is never replaced); the folder can be replaced with `KDEAICHAT_APPLICATIONS_DIR`. New module `kdeaichat/selection.py`.
- **Buttons on notifications.** The widget's notifications now carry Plasma's own action buttons: **Open chat** (opens the popup on that chat) on every one, and **Read aloud** on a finished reply while read aloud is on (the reply text stays in the widget; it is never put on a command line). Incognito chats still show no text in notifications and keep the buttons.
- **Ask KDE AI Chat from KRunner and Dolphin (Settings → Desktop integration, both off by default).** Other parts of the desktop hand a question to the widget through the **ask inbox**: one private JSON file per request (`{text, files, newChat, send}`, mode 0600) in `$XDG_RUNTIME_DIR/kdeaichat-ask/` (mode 0700, gone at logout), so a question never sits on a command line other users can read. `chat/AskInbox.qml` watches the folder (a file-system watcher, no polling; same idea as the scheduled-run inbox), takes the requests through the helper (`ask_inbox_take`: claimed by rename and deleted, so with two widgets only one gets each, requests older than a day are dropped), **opens the popup itself** (no call into plasmashell is needed), attaches files with the normal attachment code, and puts the text in the message box after anything already typed there (a request marked "send" is sent at once only when the box was empty, the files have loaded and the same chat is still open). A request goes into the open chat in that chat's own mode; **"new chat"** starts a new chat in your default mode; a request never changes a chat's mode. The stdlib command `contents/ui/scripts/kdeaichat-ask [--new-chat] [--send] [--stdin] [--file PATH] [TEXT]` writes one (use `--stdin` for private text). **KRunner:** type `ai <question>` (the word is a setting, default "ai") and choose "Ask KDE AI Chat: …" (or the action "Ask in a new chat"). It is a D-Bus runner (`org.kde.krunner1`) described by `~/.local/share/krunner/dbusplugins/kdeaichat-runner.desktop`, started on demand through `~/.local/share/dbus-1/services/org.kde.kdeaichat.runner.service` and exiting after a minute idle; it is plain Python with its own small D-Bus implementation (`kdeaichat/minidbus.py`, no python3-dbus or PyGObject needed, checked against a real session bus and gdbus). **Dolphin:** the right-click entry "Ask KDE AI Chat about this file" (KDE 6 service menu, `~/.local/share/kio/servicemenus/kdeaichat-ask.desktop`) for text, Markdown, CSV, JSON, PDF, Word documents and pictures attaches the files to your message and opens the widget. Both are installed only while their switch is on and removed when it is switched off, by the helper commands `desktop_sync` / `desktop_status` (atomic writes, only files carrying the `X-KDEAIChat-Managed` marker are ever replaced or removed; the widget re-installs them at start while a switch is on so a moved widget keeps them working). New settings `krunnerEnabled`, `krunnerPrefix`, `dolphinMenuEnabled`.

### Security
- **Pictures and keys no longer follow risky redirects.** When the widget downloads a picture, every redirect is checked again against the same rules.
